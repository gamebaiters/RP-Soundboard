GameBaiters Soundboard 1.0.21 - auto-update verification build
============================================================

This release exists primarily to verify that the auto-updater pipeline
introduced in 1.0.20 actually triggers an update for clients running an
earlier build.

What changed since 1.0.20
-------------------------
* Build number bumped 1837 -> 1838 so version.xml advertises an update
* No functional code changes vs 1.0.20

How to verify the auto-updater works
------------------------------------
* Install rp_soundboard_fx_1.0.20.ts3_plugin on TeamSpeak 3 first
* Restart TS3, enable the plugin, open the Soundboard window once so
  the UpdateChecker fires
* Within ~10 seconds the plugin contacts:
    raw.githubusercontent.com/gamebaiters/RP-Soundboard/gamebaiters/version.xml
* It reads <latestVersion>1838</latestVersion>, compares to the embedded
  TS3SB_VERSION_BUILD=1837 of the running 1.0.20 build, sees an update
* A dialog appears: "A new version of GameBaiters - Soundboard is
  available (1.0.21). Would you like to download and install it?"
  (Show details opens this release-notes.txt)
* Click Yes -> the new .ts3_plugin downloads -> the auto-updater writes
  %TEMP%\rpsb_update_helper.bat -> helper closes TS3, deletes the prior
  DLL variant, hands the new .ts3_plugin to package_inst.exe
* package_inst installs 1.0.21 -> user re-opens TS3 manually

Same fixes carry over from 1.0.20
---------------------------------
* TS3 Settings -> Plugins -> Uninstall now actually deletes the DLL
* SampleVisualizerThread is hard-stopped during shutdown
* Qt event queue drained before DLL unload
* rpsb_debug.log file handle closed cleanly
* Legacy upstream DLLs swept on plugin init
* Auto-updater helper preserves rp_soundboard.ini config
* Skip buttons (+5s/-5s/+10s/-10s) widened, dark theme restored
* Uninstall scripts ship 3-way backup prompt (Full/Config/None)
  and use cmd /k so the window stays open after completion
